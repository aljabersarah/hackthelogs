Amazon Web Services Logs

AWS Log Overview

In AWS every action is an API call, and CloudTrail records them. Launching an instance, reading a secret, attaching a policy, or deleting a bucket are all the same kind of event from the platform's perspective: an identity called an API, from an address, at a time, with parameters, and either succeeded or was denied. That uniformity is what makes CloudTrail the single most important log in any AWS environment. There is no equivalent of an unmonitored server here, because there is no way to act on AWS resources without generating an event.

CloudTrail splits into two categories that behave very differently. Management events cover control plane operations and are logged free of charge for the first copy, with 90 days of history available in the console even with no trail configured. Data events cover operations on the contents of resources, such as reading an S3 object or invoking a Lambda function, and they are disabled by default and billed by volume. This distinction produces the most common gap in AWS monitoring: an organisation records that a bucket policy was changed but has no record of the objects subsequently downloaded, because data events were never enabled.

Around CloudTrail sit several complementary sources. VPC Flow Logs capture network metadata that CloudTrail never sees, since traffic between instances involves no API call. GuardDuty applies managed detections to CloudTrail, DNS, and flow data, producing findings that are usually the fastest route to noticing credential abuse. S3 server access logs and CloudFront logs record content requests, and Config tracks resource state over time. A mature deployment uses an organisation trail delivering to a dedicated logging account that even administrators in member accounts cannot modify, which is the control that prevents an attacker from erasing their own tracks.

Key AWS Log Types

AWS produces many log types with very different coverage, cost, and default state. Knowing which are off by default is the practical starting point:

Log Type Description
CloudTrail Management Events Every control plane API call across the account: identity changes, resource creation and deletion, policy modifications, and console logins. The authoritative audit trail. Free for the first copy but only retained 90 days unless a trail delivers it to S3.
CloudTrail Data Events Operations on resource contents such as S3 GetObject and PutObject, Lambda Invoke, and DynamoDB item access. Disabled by default and billed per event. Without these you cannot prove what data an attacker actually read.
CloudTrail Insights Managed anomaly detection over management event volume, flagging unusual rates of API activity. Useful for spotting enumeration bursts and mass deletion without writing detections yourself.
VPC Flow Logs Network metadata for traffic in and out of network interfaces, including source, destination, ports, bytes, and accept or reject decisions. Captures lateral movement between instances that generates no API call and is therefore invisible to CloudTrail.
GuardDuty Findings Managed threat detection analysing CloudTrail, VPC Flow Logs, DNS query logs, EKS audit logs, and S3 data events. Produces enriched findings such as credential exfiltration and cryptomining with severity scores.
S3 Server Access Logs Detailed request records for a bucket, independent of CloudTrail data events. Higher latency and best-effort delivery, but includes fields such as the referrer and turnaround time that data events omit.
AWS Config Point-in-time snapshots of resource configuration and a timeline of changes. Answers what a security group looked like last Tuesday, which CloudTrail can only reconstruct by replaying events.
CloudWatch Logs Application and system logs shipped from EC2, Lambda, and containers. Also the destination for VPC Flow Logs and Route 53 resolver query logs when real-time analysis is needed.
Pro Tip: CloudTrail records the API call, not its effect on data. GetObject appears only if S3 data events are enabled for that bucket. An organisation that skipped data events on cost grounds cannot answer the one question that matters after a breach: which files were taken.

Log Destinations

AWS logs are delivered to services rather than filesystem paths. Where each stream lands determines how you query it and how long it survives.

Log Destination
CloudTrail Event History Console only, last 90 days of management events, not configurable and not exportable in bulk
CloudTrail Trail s3://bucket/AWSLogs/<account>/CloudTrail/<region>/YYYY/MM/DD/ as gzipped JSON
CloudTrail Lake Managed event data store queryable with SQL, retention up to 10 years
VPC Flow Logs CloudWatch Logs group, S3 bucket, or Kinesis Data Firehose
GuardDuty GuardDuty console, EventBridge events, and optional S3 export
S3 Server Access Logs A separate target bucket, delivered best-effort with delay of minutes to hours
AWS Config S3 delivery channel plus the Config console timeline
Organisation Trail A single bucket in a dedicated logging account, covering every member account centrally
Pro Tip: Console Event History is not a substitute for a trail. It covers management events only, holds 90 days, cannot be queried programmatically at scale, and disappears entirely if the account is closed. Always configure a trail delivering to S3 in a separate account.

Configuring AWS Logging

These commands establish a tamper-resistant organisation trail and the supporting log sources that CloudTrail alone does not cover.

Step 1: Create a Multi-Region Organisation Trail

aws cloudtrail create-trail \ --name htl-org-trail \ --s3-bucket-name htl-security-logs-central \ --is-organization-trail \ --is-multi-region-trail \ --enable-log-file-validation \ --kms-key-id arn:aws:kms:me-south-1:111122223333:key/abcd-1234 aws cloudtrail start-logging --name htl-org-trail
Multi-region is essential: attackers deliberately operate in regions you do not use. Log file validation produces signed digest files that prove the log has not been altered.

Step 2: Enable Data Events for Sensitive Resources

aws cloudtrail put-event-selectors \ --trail-name htl-org-trail \ --advanced-event-selectors '[ {"Name":"Management events", "FieldSelectors":[{"Field":"eventCategory","Equals":["Management"]}]}, {"Name":"S3 data events on sensitive buckets", "FieldSelectors":[ {"Field":"eventCategory","Equals":["Data"]}, {"Field":"resources.type","Equals":["AWS::S3::Object"]}, {"Field":"resources.ARN","StartsWith":["arn:aws:s3:::htl-customer-data/"]}]}]'
Scoping data events to specific buckets controls cost while preserving the ability to prove what was read. Enabling them account-wide is usually financially impractical.

Step 3: Protect the Log Bucket from Tampering

# Object Lock in compliance mode makes objects immutable, even to root aws s3api put-object-lock-configuration \ --bucket htl-security-logs-central \ --object-lock-configuration '{"ObjectLockEnabled":"Enabled", "Rule":{"DefaultRetention":{"Mode":"COMPLIANCE","Days":400}}}' # Deny deletion and policy changes from outside the security account aws s3api put-bucket-policy --bucket htl-security-logs-central \ --policy file://deny-delete-except-security-role.json aws s3api put-public-access-block --bucket htl-security-logs-central \ --public-access-block-configuration \ BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
Compliance mode Object Lock cannot be removed by anyone including the account root user. This is what guarantees an attacker with full administrative access still cannot erase the evidence.

Step 4: Enable VPC Flow Logs

aws ec2 create-flow-logs \ --resource-type VPC \ --resource-ids vpc-0a1b2c3d4e5f67890 \ --traffic-type ALL \ --log-destination-type s3 \ --log-destination arn:aws:s3:::htl-security-logs-central/vpcflow/ \ --max-aggregation-interval 60 \ --log-format '${version} ${account-id} ${interface-id} ${srcaddr} ${dstaddr} ${srcport} ${dstport} ${protocol} ${packets} ${bytes} ${start} ${end} ${action} ${log-status} ${vpc-id} ${subnet-id} ${instance-id} ${tcp-flags} ${type} ${pkt-srcaddr} ${pkt-dstaddr} ${flow-direction} ${traffic-path}'
The custom format adds fields absent from the default, notably pkt-srcaddr which reveals the original source behind a NAT gateway, and flow-direction which removes ambiguity about who initiated.

Step 5: Enable GuardDuty Across the Organisation

aws guardduty create-detector --enable \ --finding-publishing-frequency FIFTEEN_MINUTES \ --data-sources '{"S3Logs":{"Enable":true}, "Kubernetes":{"AuditLogs":{"Enable":true}}, "MalwareProtection":{"ScanEc2InstanceWithFindings":{"EbsVolumes":true}}}' aws guardduty create-members --detector-id <id> \ --account-details file://member-accounts.json aws guardduty update-organization-configuration --detector-id <id> --auto-enable
Auto-enable ensures new accounts are covered from creation. A new unmonitored account is a favourite place for an attacker to operate.

Step 6: Alert on Logging Being Disabled

{ "source": ["aws.cloudtrail"], "detail": { "eventName": ["StopLogging","DeleteTrail","UpdateTrail", "PutEventSelectors","DeleteFlowLogs", "DisassociateMembers","DeleteDetector"] } } # Attach this EventBridge rule to an SNS topic that pages, not one that emails a shared inbox
Disabling logging is among the first actions an attacker takes after gaining administrative access. This rule must reach a human within minutes.
Security Note: CloudTrail delivers to S3 with a typical latency of about five minutes and an upper bound of fifteen. An attacker who moves quickly can complete an entire operation before the first log file lands. For time-critical detection, use EventBridge rules on management events, which fire in near real time.

AWS Threat Patterns

Cloud intrusions follow a consistent arc: obtain credentials, enumerate permissions, escalate, persist, then exfiltrate. Each stage has a distinct CloudTrail signature.

Credential Compromise

Access keys leaked in code repositories or stolen from instance metadata. Signature: an existing key suddenly used from a new address, new region, or unfamiliar user agent such as an SDK version never seen before.
Detect Critical

Permission Enumeration

Rapid discovery of what the stolen identity can do. Signature: a burst of List, Describe, and Get calls across many services, often with a high proportion of AccessDenied results.
Detect Critical

Privilege Escalation

Using existing IAM permissions to acquire more. AttachUserPolicy with AdministratorAccess, CreatePolicyVersion, PassRole into a service, or UpdateAssumeRolePolicy are the classic paths.
Detect Critical

Persistence

Establishing durable access independent of the original credential. CreateAccessKey for another user, CreateUser, CreateLoginProfile, or adding an external principal to a role trust policy.
Detect Critical

Data Exfiltration

Snapshot sharing to an external account, bucket policy changes granting public access, or mass GetObject. Sharing a snapshot copies an entire database without ever reading a row through the database itself.
Detect Critical

Defence Evasion

StopLogging, DeleteTrail, DeleteFlowLogs, DeleteDetector, or operating in an unused region where monitoring was never configured. Frequently the first action after escalation.
Detect Critical
Security Note: The userAgent field is one of the most underused detection surfaces in CloudTrail. Automation uses consistent SDK strings, so an identity that normally appears as a Terraform or Boto3 user agent suddenly calling from aws-cli/2.x on a different platform is a strong indicator of stolen credentials.

CloudTrail Event Format

Every CloudTrail record shares the same JSON structure regardless of which service it came from. These are the fields that carry detection value.

Field Description Category Example Value
eventTime UTC time the API call was made Timestamp 2025-07-14T09:41:22Z
eventName The API action invoked Action AttachUserPolicy
eventSource Service that handled the call Target iam.amazonaws.com
userIdentity.type Identity class making the call Identity AssumedRole
userIdentity.arn Full ARN of the calling principal Identity arn:aws:sts::1111:assumed-role/Deploy/i-0abc
userIdentity.accessKeyId Access key used, ASIA prefix means temporary Identity AKIAIOSFODNN7EXAMPLE
sourceIPAddress Caller address, or an AWS service principal Source 203.0.113.44
userAgent SDK or tool that issued the request Source aws-cli/2.15.4 Python/3.11 Linux
awsRegion Region the call was made in Target ap-southeast-2
errorCode Present only when the call failed Result AccessDenied
requestParameters Arguments supplied to the API Action policyArn: AdministratorAccess
responseElements Values returned, including created secrets Response accessKeyId: AKIAI44QH8DHBEXAMPLE
mfaAuthenticated Whether MFA was used for this session Authorization false
readOnly Whether the call modified state Metadata false
Pro Tip: When a service makes a call on your behalf, sourceIPAddress contains a service name such as ec2.amazonaws.com rather than an address. Detections that assume this field is always an IP will silently skip every service-initiated event.

Critical API Calls to Monitor

A small number of API calls account for most of the damage in AWS intrusions. These belong on a watchlist with real-time alerting.

API Call Stage Why It Matters
StopLogging / DeleteTrail Evasion Disables the audit trail itself. Effectively never legitimate outside a documented decommissioning, and should page immediately
CreateAccessKey Persistence Creating a key for another user is a durable backdoor surviving password resets. Creating one for yourself is routine
AttachUserPolicy / AttachRolePolicy Escalation Especially with AdministratorAccess or PowerUserAccess. The single most direct route to full account control
UpdateAssumeRolePolicy Persistence Adding an external account to a role trust policy grants a permanent foothold that survives credential rotation entirely
ModifySnapshotAttribute Exfiltration Sharing an EBS or RDS snapshot with an external account copies entire volumes without touching the running system
PutBucketPolicy / PutBucketAcl Exfiltration Bucket policy changes granting public or cross-account access are the mechanism behind most large S3 data exposures
GetSecretValue / Decrypt Credential Access Bulk retrieval from Secrets Manager or KMS decryption at abnormal volume indicates credential harvesting
CreateUser / CreateLoginProfile Persistence New identities with console access created outside the provisioning pipeline are attacker backdoors
AssumeRole with external ID Lateral Movement Role chaining across accounts. Legitimate in many architectures, so baseline the normal chains and alert on new ones
DeactivateMFADevice Evasion Removing MFA from a privileged identity weakens the control specifically protecting it
RunInstances in unused regions Impact Cryptomining almost always starts in regions the organisation never uses, precisely because monitoring is thinner there

AWS Log Analysis Queries

These Athena and CLI queries cover the full intrusion arc from credential abuse through to exfiltration.

Logging Disabled
Athena> SELECT eventtime, useridentity.arn, sourceipaddress, eventname FROM cloudtrail_logs WHERE eventname IN ('StopLogging','DeleteTrail','UpdateTrail','PutEventSelectors','DeleteFlowLogs','DeleteDetector') ORDER BY eventtime DESC;
The highest priority query in AWS. Any result outside a documented change is an active incident.
Privilege Escalation
Athena> SELECT eventtime, useridentity.arn, eventname, requestparameters FROM cloudtrail_logs WHERE eventname IN ('AttachUserPolicy','AttachRolePolicy','PutUserPolicy','CreatePolicyVersion','UpdateAssumeRolePolicy') AND requestparameters LIKE '%Administrator%';
Catches administrative policy attachment in one query. Reconcile every hit against a change ticket.
Permission Enumeration
Athena> SELECT useridentity.arn, sourceipaddress, count(*) AS denied, count(DISTINCT eventsource) AS services FROM cloudtrail_logs WHERE errorcode = 'AccessDenied' AND from_iso8601_timestamp(eventtime) > current_timestamp - interval '1' hour GROUP BY 1,2 HAVING count(*) > 25;
Many AccessDenied results across many services is an attacker mapping what a stolen credential can reach.
Snapshot Shared Externally
Athena> SELECT eventtime, useridentity.arn, requestparameters FROM cloudtrail_logs WHERE eventname IN ('ModifySnapshotAttribute','ModifyDBSnapshotAttribute','ModifyImageAttribute') AND requestparameters LIKE '%all%' OR requestparameters LIKE '%restore%';
Sharing a snapshot with another account or making it public exfiltrates an entire volume in one API call.
Access Key Created for Another User
Athena> SELECT eventtime, useridentity.arn AS creator, json_extract_scalar(requestparameters,'$.userName') AS target, sourceipaddress FROM cloudtrail_logs WHERE eventname = 'CreateAccessKey' AND json_extract_scalar(requestparameters,'$.userName') IS NOT NULL;
When userName is present the key was created for a different identity, which is the backdoor pattern rather than routine self-service.
Activity in Unused Regions
Athena> SELECT awsregion, eventname, useridentity.arn, count(*) AS calls FROM cloudtrail_logs WHERE awsregion NOT IN ('me-south-1','eu-west-1') AND readonly = false GROUP BY 1,2,3 ORDER BY calls DESC;
Attackers favour regions you do not use because monitoring and guardrails are weaker there. Any write activity is worth review.
Root Account Usage
Athena> SELECT eventtime, eventname, sourceipaddress, useragent, useridentity.sessioncontext.attributes.mfaauthenticated AS mfa FROM cloudtrail_logs WHERE useridentity.type = 'Root' ORDER BY eventtime DESC;
Root should be used essentially never. Any usage, especially without MFA, warrants immediate confirmation with the account owner.
User Agent Anomaly
Athena> SELECT useridentity.arn, useragent, count(*) AS calls, min(eventtime) AS first_seen FROM cloudtrail_logs GROUP BY 1,2 HAVING min(from_iso8601_timestamp(eventtime)) > current_timestamp - interval '24' hour ORDER BY calls DESC;
A new user agent for an established identity often means the credential is now being used by someone else's tooling.
Bulk S3 Object Reads
Athena> SELECT useridentity.arn, sourceipaddress, count(*) AS objects FROM cloudtrail_logs WHERE eventname = 'GetObject' AND eventcategory = 'Data' GROUP BY 1,2 HAVING count(*) > 1000 ORDER BY objects DESC;
Requires data events to be enabled. Without them this query returns nothing regardless of how much data was taken.
Outbound Volume from Flow Logs
Athena> SELECT srcaddr, dstaddr, sum(bytes)/1073741824.0 AS gb FROM vpc_flow_logs WHERE action='ACCEPT' AND flow_direction='egress' GROUP BY 1,2 HAVING sum(bytes) > 10737418240 ORDER BY gb DESC;
Finds instances sending more than 10 GB outbound. Catches exfiltration that never involves an S3 API call.

Best Practices for AWS Logging

Apply these practices so that AWS logs remain complete, immutable, and actually queryable during an incident:

01

Use an Organisation Trail to a Separate Account

Logs must live where the compromised account cannot reach them. A dedicated logging account with restrictive bucket policies is the single most important control in AWS logging architecture.

02

Always Enable Multi-Region

Attackers deliberately operate in regions you never use. A single-region trail leaves every other region completely unmonitored while appearing configured.

03

Enable Data Events on Sensitive Buckets

Management events prove a policy changed. Only data events prove which objects were read. Scope them to the buckets holding regulated data to keep the cost defensible.

04

Apply Object Lock in Compliance Mode

Compliance mode retention cannot be shortened or removed by anyone, including the root user. It is what makes the audit trail genuinely tamper-proof rather than merely protected.

05

Turn On Log File Validation

CloudTrail produces signed digest files that let you prove logs were not altered or deleted. Essential for any investigation whose findings might be disputed.

06

Use EventBridge for Time-Critical Alerts

S3 delivery lags by five to fifteen minutes, long enough for an attacker to finish. EventBridge rules on management events fire in near real time.

07

Baseline Identity Behaviour

Record the normal region, source address, and user agent for every role and key. Deviation from that baseline is the most reliable signal of credential theft available.

08

Do Not Rely on Console Event History

It holds 90 days of management events only, cannot be exported in bulk, and vanishes with the account. It is a convenience feature, not an audit trail.

Common AWS Log Examples

A complete AWS intrusion in CloudTrail records, from leaked key to exfiltrated database.

Stolen Access Key Used from a New Location

{"eventTime":"2025-07-14T09:41:22Z","eventName":"GetCallerIdentity","eventSource":"sts.amazonaws.com", "awsRegion":"us-east-1","sourceIPAddress":"203.0.113.44", "userAgent":"aws-cli/2.15.4 Python/3.11.6 Linux/6.1.0 exe/x86_64.kali", "userIdentity":{"type":"IAMUser","arn":"arn:aws:iam::111122223333:user/svc-backup", "accessKeyId":"AKIAIOSFODNN7EXAMPLE"},"readOnly":true}
GetCallerIdentity is the first call almost every attacker makes: it answers "whose key is this". The user agent contains "kali" and the region is one this service account never uses.

Permission Enumeration with Access Denied

{"eventTime":"2025-07-14T09:42:04Z","eventName":"ListBuckets","eventSource":"s3.amazonaws.com","errorCode":"AccessDenied","sourceIPAddress":"203.0.113.44"} {"eventTime":"2025-07-14T09:42:06Z","eventName":"ListUsers","eventSource":"iam.amazonaws.com","errorCode":"AccessDenied","sourceIPAddress":"203.0.113.44"} {"eventTime":"2025-07-14T09:42:08Z","eventName":"DescribeInstances","eventSource":"ec2.amazonaws.com","sourceIPAddress":"203.0.113.44","readOnly":true} {"eventTime":"2025-07-14T09:42:11Z","eventName":"ListAttachedUserPolicies","eventSource":"iam.amazonaws.com","sourceIPAddress":"203.0.113.44","readOnly":true} {"eventTime":"2025-07-14T09:42:14Z","eventName":"DescribeDBSnapshots","eventSource":"rds.amazonaws.com","sourceIPAddress":"203.0.113.44","readOnly":true}
Five services probed in ten seconds with a mix of denials and successes. No human clicks this fast, and the mixed results are the attacker mapping the boundary of what the key permits.

Privilege Escalation via Policy Attachment

{"eventTime":"2025-07-14T09:47:33Z","eventName":"AttachUserPolicy","eventSource":"iam.amazonaws.com", "sourceIPAddress":"203.0.113.44","userIdentity":{"type":"IAMUser","arn":"arn:aws:iam::111122223333:user/svc-backup"}, "requestParameters":{"userName":"svc-backup","policyArn":"arn:aws:iam::aws:policy/AdministratorAccess"}, "responseElements":null,"readOnly":false}
The compromised service account attaching AdministratorAccess to itself. This single call converts a limited backup credential into full control of the account.

Persistence: Backdoor Key for Another User

{"eventTime":"2025-07-14T09:52:10Z","eventName":"CreateAccessKey","eventSource":"iam.amazonaws.com", "sourceIPAddress":"203.0.113.44","userIdentity":{"arn":"arn:aws:iam::111122223333:user/svc-backup"}, "requestParameters":{"userName":"cloudops-admin"}, "responseElements":{"accessKey":{"accessKeyId":"AKIAI44QH8DHBEXAMPLE","userName":"cloudops-admin","status":"Active"}}}
A key created for a different, more privileged user. This survives rotation of the original stolen credential entirely, which is exactly the point.

Cross-Account Persistence via Trust Policy

{"eventTime":"2025-07-14T09:55:41Z","eventName":"UpdateAssumeRolePolicy","eventSource":"iam.amazonaws.com", "sourceIPAddress":"203.0.113.44","requestParameters":{"roleName":"OrganizationAccountAccessRole", "policyDocument":"{\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\", \"Principal\":{\"AWS\":\"arn:aws:iam::999988887777:root\"},\"Action\":\"sts:AssumeRole\"}]}"}}
An external account (999988887777) added to the trust policy of a privileged role. The attacker can now assume this role from their own account indefinitely, with no credential to rotate.

Data Exfiltration via Snapshot Sharing

{"eventTime":"2025-07-14T10:02:44Z","eventName":"CreateDBSnapshot","eventSource":"rds.amazonaws.com", "requestParameters":{"dBInstanceIdentifier":"prod-customers","dBSnapshotIdentifier":"tmp-snap-01"}} {"eventTime":"2025-07-14T10:11:03Z","eventName":"ModifyDBSnapshotAttribute","eventSource":"rds.amazonaws.com", "sourceIPAddress":"203.0.113.44", "requestParameters":{"dBSnapshotIdentifier":"tmp-snap-01","attributeName":"restore", "valuesToAdd":["999988887777"]}}
The entire customer database snapshotted then shared with an external account. Note that no database query was ever run, so database audit logs show nothing at all.

S3 Bucket Exposed Publicly

{"eventTime":"2025-07-14T10:14:22Z","eventName":"PutBucketPolicy","eventSource":"s3.amazonaws.com", "sourceIPAddress":"203.0.113.44","requestParameters":{"bucketName":"htl-customer-data", "bucketPolicy":{"Statement":[{"Effect":"Allow","Principal":"*","Action":"s3:GetObject", "Resource":"arn:aws:s3:::htl-customer-data/*"}]}}} {"eventTime":"2025-07-14T10:14:31Z","eventName":"DeletePublicAccessBlock","eventSource":"s3.amazonaws.com", "requestParameters":{"bucketName":"htl-customer-data"}}
A wildcard principal granted read access, then the public access block removed so the policy takes effect. Both calls are needed, and either one alone should alert.

Defence Evasion: Trail Stopped

{"eventTime":"2025-07-14T10:18:12Z","eventName":"StopLogging","eventSource":"cloudtrail.amazonaws.com", "sourceIPAddress":"203.0.113.44","userIdentity":{"arn":"arn:aws:iam::111122223333:user/svc-backup"}, "requestParameters":{"name":"arn:aws:cloudtrail:me-south-1:111122223333:trail/htl-org-trail"}} {"eventTime":"2025-07-14T10:18:19Z","eventName":"DeleteFlowLogs","eventSource":"ec2.amazonaws.com", "requestParameters":{"flowLogIdSet":["fl-0a1b2c3d4e5f67890"]}}
The trail is stopped and flow logs deleted. Because the log bucket used Object Lock in compliance mode, everything already written survives, which is why these two records exist at all.

Cryptomining in an Unused Region

{"eventTime":"2025-07-14T10:24:18Z","eventName":"RunInstances","eventSource":"ec2.amazonaws.com", "awsRegion":"ap-southeast-2","sourceIPAddress":"203.0.113.44", "requestParameters":{"instanceType":"p4d.24xlarge","maxCount":8,"minCount":8, "imageId":"ami-0abcdef1234567890"},"readOnly":false}
Eight GPU instances launched in a region the organisation does not operate in. At roughly 32 USD per hour each, this becomes expensive within hours and is usually noticed by billing before security.
