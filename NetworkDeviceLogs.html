Router and Switch Logs

Network Device Log Overview

Routers and switches are the infrastructure every other system depends on, and they are consistently the least monitored assets in the estate. An attacker who compromises a core switch can mirror traffic to a collector, alter routing to intercept sessions, disable access control lists, and modify the very logging that would reveal any of it. Network devices are also increasingly targeted directly, with state-aligned actors known to persist on routers for years because nobody was watching the configuration.

These devices log through syslog, and the critical architectural fact is that they retain almost nothing locally. A Cisco switch keeps a small in-memory buffer that wraps within minutes on a busy device and is cleared entirely by a reboot. There is no local disk log to recover after an incident. If syslog forwarding is not configured, the evidence does not exist. That single property makes network device logging an all-or-nothing proposition in a way that server logging is not.

The most valuable records fall into three groups. Configuration and authentication events reveal who logged into the management plane and what they changed, which is the core of detecting device compromise. Access control list denials provide segmentation enforcement evidence and reveal lateral movement attempts between zones. Port security and 802.1X events expose unauthorised devices connecting to physical ports. Command accounting through TACACS+ goes further still, recording every individual command an administrator typed rather than merely that a configuration change occurred.

Key Network Device Log Types

Network devices emit several categories of message. Only some carry security value, and separating them is the key to a manageable event rate:

Log Type Description
Configuration Change Log Records entry into configuration mode and, with the archive feature, the exact commands applied. The single most important stream on any network device: every attacker modification to routing, access control, or logging appears here.
Authentication and Authorisation Log Management plane logins over SSH, console, and the web interface, plus privilege escalation to enable mode. Failed authentication bursts against infrastructure are a strong precursor to device compromise.
ACL Denial Log Packets dropped by access control lists, subject to the log keyword being present on the entry. The primary evidence that network segmentation is being enforced and the primary detection for lateral movement between zones.
Port Security and 802.1X Log Violations where an unexpected MAC address appeared on a port, and results of port-based authentication. Detects unauthorised devices plugged into physical infrastructure, including rogue access points and drop boxes.
Interface State Log Link up and down transitions and line protocol changes. Mostly operational, but an interface coming up on a previously unused port, or repeated flapping, can indicate physical tampering.
Routing Protocol Log Neighbour adjacency changes for OSPF, BGP, and EIGRP. An unexpected new neighbour is a serious event, since a rogue peer can inject routes that redirect traffic through attacker infrastructure.
Command Accounting Delivered through TACACS+ rather than syslog. Records every command executed by every administrator with full attribution. The gold standard for management plane auditing and worth deploying for this alone.
Spanning Tree and Layer 2 Log Root bridge changes, BPDU guard actions, and loop detection. A spanning tree topology change caused by an unauthorised device can redirect entire VLANs through an attacker-controlled path.
Pro Tip: ACL denials are only logged when the log or log-input keyword is present on the individual access list entry. A device with a hundred ACL lines and no log keywords produces perfect enforcement and zero visibility. Add log-input to deny entries specifically, since it also records the ingress interface and source MAC.

Log Destinations

Unlike servers, network devices have no meaningful local log storage. These are the destinations available and their retention characteristics.

Destination Characteristics
Memory Buffer Cisco: viewed with show logging. Typically 4 to 16 KB by default, wraps within minutes, and is lost completely on reload. Useful for live troubleshooting only
Remote Syslog The only viable collection method. Configured with logging host on Cisco or set system syslog host on Junos. Should use TCP with TLS where the platform supports it
Console and Terminal Lines Real time display to an attached session. Console logging at high verbosity can hang the device under load and should be disabled in production
Configuration Archive Cisco archive feature storing configuration snapshots to flash or a remote server, with the log config subcommand capturing individual commands
TACACS+ Accounting Command level accounting sent to an authentication server such as Cisco ISE. Retained centrally with full attribution, independent of syslog
SNMP Traps Event notifications to a network management platform. Useful for availability monitoring but a poor security log, as trap coverage is inconsistent
Junos Local Files /var/log/messages, /var/log/interactive-commands, and /var/log/authorization. Junos retains more locally than IOS but still requires forwarding
Flash Storage Some platforms support logging to onboard flash. Survives reload but has limited capacity and is erasable by anyone with device access
Pro Tip: Run show logging before you do anything else when responding to a suspected device compromise. The buffer holds the most recent events and will be destroyed by the reload that is often the first instinct during troubleshooting.

Configuring Network Device Logging

These configurations produce attributable, timestamped, centrally stored records from Cisco IOS and Juniper Junos devices.

Step 1: Configure Cisco IOS Syslog

service timestamps log datetime msec localtime show-timezone year service sequence-numbers logging buffered 65536 informational no logging console logging host 10.50.9.20 transport tcp port 1514 logging trap informational logging source-interface Loopback0 logging origin-id hostname logging facility local6
The timestamp directive is critical. IOS defaults to uptime rather than wall clock time, producing entries like "3d04h" that are useless for correlation. Sequence numbers reveal messages lost in transit.

Step 2: Enable Configuration Change Logging

archive log config logging enable logging size 1000 notify syslog contenttype plaintext hidekeys path tftp://10.50.9.30/$h-config write-memory time-period 10080
Without this, a configuration change produces only a generic CONFIG_I message saying something changed. With it, every individual command is logged and attributed. hidekeys prevents passwords appearing in the log.

Step 3: Log Authentication Events

login on-failure log every 1 login on-success log every 1 login block-for 300 attempts 5 within 60 aaa new-model aaa authentication login default group tacacs+ local aaa authorization commands 15 default group tacacs+ local aaa accounting commands 15 default start-stop group tacacs+ aaa accounting exec default start-stop group tacacs+
Success and failure logging are both off by default. Command accounting at privilege 15 is what records every individual command an administrator runs, with full attribution.

Step 4: Add Logging to Access Control Lists

ip access-list extended SEGMENT-USERS-TO-SERVERS permit tcp 10.30.0.0 0.0.255.255 10.40.1.0 0.0.0.255 eq 443 deny ip 10.30.0.0 0.0.255.255 10.40.1.0 0.0.0.255 log-input deny ip any any log-input ! ip access-list logging interval 250 logging rate-limit 100 except critical
log-input records the ingress interface and source MAC alongside the packet, which is what turns a denial into an investigable event. Rate limiting protects the control plane from a logging-induced denial of service.

Step 5: Enable Port Security and Layer 2 Protection

interface range GigabitEthernet1/0/2 - 48 switchport mode access switchport port-security switchport port-security maximum 2 switchport port-security violation restrict switchport port-security aging time 120 spanning-tree bpduguard enable spanning-tree portfast ! errdisable recovery cause psecure-violation errdisable recovery interval 300
The restrict violation mode drops offending traffic and logs it, whereas shutdown disables the port entirely and protect drops silently with no log at all. Only restrict gives both enforcement and visibility.

Step 6: Configure Juniper Junos Logging

set system syslog host 10.50.9.20 any notice set system syslog host 10.50.9.20 authorization info set system syslog host 10.50.9.20 interactive-commands any set system syslog host 10.50.9.20 change-log any set system syslog host 10.50.9.20 structured-data set system syslog host 10.50.9.20 source-address 10.50.1.5 set system syslog file interactive-commands interactive-commands any set system syslog time-format year millisecond
The interactive-commands and change-log facilities are Junos equivalents of Cisco command accounting. structured-data emits RFC 5424 format, which parses far more reliably than the legacy format.
Security Note: Traditional syslog over UDP is unauthenticated and unencrypted, so anyone on the path can forge or read device logs. Use TCP with TLS where supported, restrict the syslog destination with an access control list, and treat the syslog collector as a tier zero asset.

Syslog Severity Levels

Syslog severity runs from 0 to 7 with lower numbers being more severe. Setting the trap level too low is the most common cause of missing security events, because most authentication and configuration messages sit at level 5 and 6.

0 to 2: Emergency, Alert, Critical

System unusable, immediate action required, or critical condition. Includes port security violations at level 2 and hardware failures. Always page on these.
Alert Critical

3: Error

Error conditions including interface link failures and IKE negotiation problems. Operationally important and occasionally security relevant.
Collect High Risk

4: Warning

Warning conditions including failed login attempts on many platforms. The default trap level on Cisco, which is precisely why level 5 and 6 events go missing.
Collect High Risk

5: Notification

Normal but significant conditions. Configuration changes (CONFIG_I), successful logins, and line protocol changes all sit here. Security critical despite the modest name.
Collect Critical

6: Informational

Informational messages including ACL denials (IPACCESSLOGP) and login successes. The correct trap level for security monitoring, and the reason to move off the default.
Collect Critical

7: Debug

Debug level messages. Enormous volume and capable of destabilising the device under load. Enable only during active troubleshooting and never as a standing configuration.
Avoid Medium Risk
Security Note: Set logging trap informational rather than accepting the default. Configuration changes are severity 5 and ACL denials are severity 6, so a device left at the warning default silently discards the two most valuable security streams it produces.

Cisco IOS messages follow a rigid structure. Parsing the mnemonic correctly is what makes detection rules portable across a fleet.

Field Description Category Example Value

Critical Device Messages

These Cisco IOS mnemonics carry the highest security value. Junos equivalents are noted where they differ substantially.

Message Meaning Why It Matters
%SYS-5-CONFIG_I Configuration changed from a source Every device modification passes through this. Correlate against your change window and ticket system, and alert on anything unmatched
%PARSER-5-CFGLOG_LOGGEDCMD Individual configuration command executed Produced by the archive log config feature. Shows the exact command rather than merely that a change occurred
%SEC_LOGIN-4-LOGIN_FAILED Management login failed Failed authentication against infrastructure. Bursts from one source are brute force against the management plane
%SEC_LOGIN-5-LOGIN_SUCCESS Management login succeeded The baseline for detecting logins outside change windows or from unexpected addresses
%SEC_LOGIN-1-QUIET_MODE_ON Login blocking activated after repeated failures Confirms a brute force attempt reached the configured threshold. Severity 1 makes it hard to miss
%SEC-6-IPACCESSLOGP Packet permitted or denied by an ACL Segmentation enforcement evidence. Denials between security zones frequently reveal lateral movement attempts
%PORT_SECURITY-2-PSECURE_VIOLATION Unauthorised MAC address on a secured port An unexpected device connected to physical infrastructure. Severity 2 and always worth investigating
%SPANTREE-2-BLOCK_BPDUGUARD BPDU received on a port with BPDU guard Someone connected a switch to an access port. Either shadow IT or an attempt to manipulate the layer 2 topology
%DOT1X-5-FAIL 802.1X authentication failed on a port A device failed port-based authentication. Repeated failures on one port indicate an unauthorised connection attempt
%BGP-5-ADJCHANGE BGP neighbour state changed An unexpected new peer can inject routes that redirect traffic through attacker-controlled infrastructure
%SYS-5-RELOAD Device reload requested Clears the memory buffer entirely. An unscheduled reload may be an attempt to destroy volatile evidence
%SYS-6-LOGGINGHOST_STARTSTOP Syslog host configuration changed Removal of a logging destination is a hallmark anti-forensic step and should page immediately
Pro Tip: Alert on the absence of logs as well as their content. A device that normally emits a steady trickle of messages and then goes silent has either failed, been reloaded, or had its logging destination removed. All three matter.

Network Device Log Analysis Queries

These queries surface unauthorised configuration changes, management plane attacks, and rogue devices on physical ports.

Configuration Changes Outside the Window
SIEM> source="network_device" mnemonic="CONFIG_I" | eval hr=strftime(_time,"%H"), dow=strftime(_time,"%a") | where NOT (dow=="Sat" AND hr>=22) AND NOT (hr>=1 AND hr<=4) | table _time, device_id, user, src_ip, message
Every change outside the approved maintenance window, ready to reconcile against tickets. Unmatched entries are the investigation queue.
Management Plane Brute Force
SIEM> source="network_device" mnemonic IN ("LOGIN_FAILED","AUTHFAIL") | bucket _time span=10m | stats count, dc(device_id) as devices, values(user) by src_ip, _time | where count > 10
A source failing against multiple devices is sweeping your infrastructure with a credential list, not mistyping a password.
Logging Destination Removed
SIEM> source="network_device" (message="*no logging host*" OR message="*no logging trap*" OR mnemonic="LOGGINGHOST_STARTSTOP" OR message="*no aaa accounting*") | table _time, device_id, user, src_ip, message
Page on this immediately. It is almost never a legitimate change and it is usually the last message that device will ever send you.
Port Security Violations
SIEM> source="network_device" mnemonic="PSECURE_VIOLATION" | stats count, values(mac_address), values(interface) by device_id | sort - count
Names the switch, the port, and the offending hardware address, which is enough to physically locate the unauthorised device.
Cross-Zone ACL Denials
SIEM> source="network_device" mnemonic="IPACCESSLOGP" action="denied" | stats count, dc(dest_ip) as targets, dc(dest_port) as ports by src_ip | where targets > 10 OR ports > 10 | sort - targets
One internal source denied against many destinations or ports is scanning across a segmentation boundary, which is textbook lateral movement.
Unexpected Routing Neighbours
SIEM> source="network_device" mnemonic IN ("ADJCHANGE","NBRCHANGE","NEIGHBOR") | stats values(neighbor_ip), count by device_id | search NOT neighbor_ip IN ("10.50.1.1","10.50.1.2","10.50.1.3")
Compare observed adjacencies against the approved topology. A rogue peer can inject routes and redirect entire subnets.
Layer 2 Topology Attacks
SIEM> source="network_device" mnemonic IN ("BLOCK_BPDUGUARD","ROOTGUARD_BLOCK","TOPOTRAP","LOOPGUARD_BLOCK") | table _time, device_id, interface, message
BPDU guard firing means a switch was connected to an access port. Root guard firing means something tried to become the spanning tree root.
Command Accounting Review
SIEM> source="tacacs" service="shell" | search cmd IN ("no logging*","no aaa*","monitor session*","username*","snmp-server*","ip nat*") | table _time, user, device_id, cmd
A watchlist of commands that create backdoors, mirror traffic, or disable auditing. Command accounting is what makes this level of detail possible.
Traffic Mirroring Configured
SIEM> source="network_device" (message="*monitor session*" OR message="*port-mirror*" OR message="*analyzer*") | table _time, device_id, user, src_ip, message
A SPAN session created outside a documented troubleshooting exercise means someone is copying traffic to a destination of their choosing.
Silent Devices
SIEM> source="network_device" earliest=-24h | stats latest(_time) as last_seen by device_id | eval age_hr=(now()-last_seen)/3600 | where age_hr > 6 | sort - age_hr
Devices that have stopped logging. Given that these devices retain nothing locally, silence means total loss of visibility rather than a quiet period.

Best Practices for Network Device Logging

Follow these practices to make infrastructure logging complete and trustworthy:

01

Fix Timestamps Before Anything Else

IOS defaults to uptime rather than wall clock time. Configure service timestamps with datetime, msec, timezone, and year, and synchronise every device to NTP or correlation is impossible.

02

Set Trap Level to Informational

Configuration changes are severity 5 and ACL denials are severity 6. The default warning level discards both, which removes the two most useful security streams the device produces.

03

Enable Archive Log Config

Without it a change produces only a generic notification. With it you get the exact command, the user, and the source, which is the difference between knowing something changed and knowing what.

04

Deploy TACACS+ Command Accounting

Per-command attribution is the strongest management plane audit available, and it is stored on the authentication server independently of syslog, so it survives device compromise.

05

Add log-input to Deny Entries

ACLs enforce silently unless the log keyword is present. log-input additionally records the ingress interface and source MAC, turning a denial into something investigable.

06

Use restrict for Port Security

The protect mode drops violating traffic with no log at all, and shutdown creates an outage. Only restrict gives you both enforcement and a record of what happened.

07

Rate Limit Logging

ACL denial logging is punted to the control plane processor. Without logging rate-limit, a deliberate flood of denied packets can degrade or crash the device.

08

Monitor for Silence

These devices hold nothing locally. A device that stops sending logs has lost all visibility, so absence of events must be alerted on as loudly as their content.

Management Plane Brute Force

001284: Jul 14 2025 09:12:04.117 AST: %SEC_LOGIN-4-LOGIN_FAILED: Login failed [user: admin] [Source: 203.0.113.44] [localport: 22] [Reason: Login Authentication Failed] at 09:12:04 AST Mon Jul 14 2025 001285: Jul 14 2025 09:12:09.882 AST: %SEC_LOGIN-4-LOGIN_FAILED: Login failed [user: cisco] [Source: 203.0.113.44] [localport: 22] [Reason: Login Authentication Failed] at 09:12:09 AST Mon Jul 14 2025 001286: Jul 14 2025 09:12:15.229 AST: %SEC_LOGIN-4-LOGIN_FAILED: Login failed [user: netadmin] [Source: 203.0.113.44] [localport: 22] [Reason: Login Authentication Failed] at 09:12:15 AST Mon Jul 14 2025 001287: Jul 14 2025 09:12:20.441 AST: %SEC_LOGIN-1-QUIET_MODE_ON: Still timeleft for watching failures is 285 seconds, [user: netadmin] [Source: 203.0.113.44] [localport: 22] [Reason: Login Authentication Failed]
Default vendor usernames tried in sequence from an external address. QUIET_MODE_ON confirms login blocking engaged, which means the threshold configured in step 3 was reached.

Successful Login and Configuration Change

001402: Jul 14 2025 09:40:53.221 AST: %SEC_LOGIN-5-LOGIN_SUCCESS: Login Success [user: netadmin] [Source: 10.99.4.117] [localport: 22] at 09:40:53 AST Mon Jul 14 2025 001403: Jul 14 2025 09:41:02.118 AST: %SYS-5-CONFIG_I: Configured from console by netadmin on vty0 (10.99.4.117)
Note the source: 10.99.4.117 is a VPN pool address. Cross-referencing the VPN session log identifies which user held that lease, and whether their account was already compromised.

Individual Commands via Archive Logging

001404: Jul 14 2025 09:41:14.882 AST: %PARSER-5-CFGLOG_LOGGEDCMD: User:netadmin logged command:monitor session 1 source vlan 40 001405: Jul 14 2025 09:41:22.104 AST: %PARSER-5-CFGLOG_LOGGEDCMD: User:netadmin logged command:monitor session 1 destination interface Gi1/0/24 001406: Jul 14 2025 09:41:38.771 AST: %PARSER-5-CFGLOG_LOGGEDCMD: User:netadmin logged command:username svc_backup privilege 15 secret ***** 001407: Jul 14 2025 09:41:55.229 AST: %PARSER-5-CFGLOG_LOGGEDCMD: User:netadmin logged command:no logging host 10.50.9.20
The full attack in four commands: mirror the server VLAN to a port, create a privileged backdoor account, then remove the syslog destination. Without archive log config, all of this would appear as a single CONFIG_I message.

Unauthorised Device on a Physical Port

001450: Jul 14 2025 09:52:10.774 AST: %PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by MAC address 000c.298f.2a41 on port GigabitEthernet1/0/24. 001451: Jul 14 2025 09:52:10.881 AST: %PM-4-ERR_DISABLE: psecure-violation error detected on Gi1/0/24, putting Gi1/0/24 in err-disable state 001452: Jul 14 2025 09:52:11.004 AST: %SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port GigabitEthernet1/0/24 with BPDU Guard enabled. Disabling port.
The same port used as the SPAN destination now shows an unknown MAC and is sending BPDUs, meaning a switch or virtual machine was plugged in there. The 000c.29 prefix is VMware.

Lateral Movement Blocked by an ACL

001478: Jul 14 2025 10:02:44.229 AST: %SEC-6-IPACCESSLOGP: list SEGMENT-USERS-TO-SERVERS denied tcp 10.30.2.61(52190) (GigabitEthernet1/0/12 0015.5d8a.4c12) -> 10.40.1.15(445), 1 packet 001479: Jul 14 2025 10:02:44.334 AST: %SEC-6-IPACCESSLOGP: list SEGMENT-USERS-TO-SERVERS denied tcp 10.30.2.61(52191) (GigabitEthernet1/0/12 0015.5d8a.4c12) -> 10.40.1.16(445), 1 packet 001480: Jul 14 2025 10:02:44.441 AST: %SEC-6-IPACCESSLOGP: list SEGMENT-USERS-TO-SERVERS denied tcp 10.30.2.61(52192) (GigabitEthernet1/0/12 0015.5d8a.4c12) -> 10.40.1.17(445), 1 packet
A workstation sweeping SMB across the server segment. The log-input keyword supplied the ingress interface and source MAC, so the offending machine is identified without any further lookup.

Rogue Routing Neighbour

001502: Jul 14 2025 10:11:03.118 AST: %OSPF-5-ADJCHG: Process 1, Nbr 10.30.2.61 on GigabitEthernet1/0/12 from LOADING to FULL, Loading Done 001503: Jul 14 2025 10:11:04.229 AST: %OSPF-4-ERRRCV: Received invalid packet: mismatched area ID, from backbone area must be virtual-link but not found from 10.30.2.61, GigabitEthernet1/0/12
An OSPF adjacency formed with a host on a user access port. No workstation should ever be an OSPF neighbour. This peer can now inject routes and pull traffic through itself.

Junos Structured Logging: Commit and Command Audit

<165>1 2025-07-14T10:18:12.774+03:00 rtr-edge-01 mgd 4218 UI_CMDLINE_READ_LINE [junos@2636.1.1.1.2.29 username="netadmin" command="delete system syslog host 10.50.9.20"] <165>1 2025-07-14T10:18:31.008+03:00 rtr-edge-01 mgd 4218 UI_COMMIT [junos@2636.1.1.1.2.29 username="netadmin" source="cli" message="none"] <164>1 2025-07-14T10:14:02.441+03:00 rtr-edge-01 sshd 3881 SSHD_LOGIN_FAILED [junos@2636.1.1.1.2.29 username="root" source-address="203.0.113.44"]
Junos structured syslog carries the username and full command as named fields rather than embedded in free text, which parses far more reliably than the IOS format.

Evidence Destruction: Unscheduled Reload

001540: Jul 14 2025 10:24:18.229 AST: %SYS-5-CONFIG_I: Configured from console by netadmin on vty0 (10.99.4.117) 001541: Jul 14 2025 10:24:31.774 AST: %SYS-5-RELOAD: Reload requested by netadmin on vty0 (10.99.4.117). Reload Reason: Reload Command.
A reload clears the in-memory buffer completely. Because syslog forwarding had already been removed in an earlier command, these two lines are the last records the collector ever received from this device.
