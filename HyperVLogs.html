Hyper-V Logs

Hyper-V Log Overview

Hyper-V logging differs fundamentally from vSphere in one respect that shapes everything else: the hypervisor runs on Windows Server, so the host produces the full set of Windows Security, System, and Application events alongside its virtualisation-specific channels. A compromised Hyper-V host generates event 4624 for the logon, 4672 for the privileges assigned, and 4688 for the process created, exactly as any Windows server would. Hyper-V events sit on top of that foundation rather than replacing it, which means an organisation with mature Windows logging already has most of what it needs.

The virtualisation channels themselves are numerous and narrowly scoped. Hyper-V-VMMS records the Virtual Machine Management Service: creation, deletion, import, export, and migration of virtual machines. Hyper-V-Worker records the per-machine worker process handling power state and runtime events. Hyper-V-VMSwitch covers virtual networking including port and mirroring configuration, and Hyper-V-Compute covers the newer host compute service used by containers and modern management tooling. Most are enabled by default but sized small, and several useful channels are analytic or debug channels that are disabled entirely.

The distinctive Hyper-V blind spot is PowerShell Direct. An administrator on the host can open a session inside any running virtual machine using Enter-PSSession -VMName, which travels over the VMBus rather than the network. It bypasses the guest firewall, produces no network connection, and appears in no network log. The guest records a logon, but nothing indicates it arrived through the hypervisor. Detecting this requires correlating host-side PowerShell operational logs with guest logons, and it is the technique most likely to be missed entirely.

Key Hyper-V Log Channels

Hyper-V spreads its events across many narrow channels. These are the ones that carry security value:

Channel Description
Hyper-V-VMMS The Virtual Machine Management Service, covering creation, deletion, import, export, checkpoint, and migration of virtual machines. The primary lifecycle channel and the one that records bulk exfiltration through export operations.
Hyper-V-Worker Per-machine worker process events including power state transitions, saved state operations, and runtime errors. Where mass power-off preceding an attack becomes visible.
Hyper-V-VMSwitch Virtual switch operations covering port creation, VLAN assignment, and port mirroring configuration. Enabling mirroring on a virtual port copies another machine's traffic to an attacker-controlled guest.
Hyper-V-Compute The Host Compute Service used by containers, WSL, and modern management APIs. Increasingly the channel through which programmatic virtual machine manipulation appears.
Hyper-V-Config Configuration file access and modification for virtual machines, including errors reading VMCX files. Useful for spotting direct tampering with machine definitions on disk.
Windows Security Log The host is a Windows server, so 4624 logons, 4672 special privileges, 4688 process creation, and 5140 share access all apply. Frequently more informative than the Hyper-V channels themselves.
PowerShell Operational Microsoft-Windows-PowerShell/Operational with script block logging enabled. The only host-side record of PowerShell Direct sessions into guest machines.
Hyper-V-High-Availability Failover clustering events for clustered Hyper-V, covering machine movement between nodes. Unexpected migrations can indicate an attacker relocating a target to a host they control.
SCVMM Job History System Center Virtual Machine Manager records administrative jobs with the initiating user. Where a management layer is deployed, this is the attribution source.
Pro Tip: Because the Hyper-V host is a domain-joined Windows server, an attacker with Hyper-V Administrators group membership gains full control of every guest without ever holding Domain Admin. Audit that group as closely as you audit Domain Admins, because it is functionally equivalent in a virtualised estate.

Log and File Locations

Event channels live in the standard Windows event log directory. Virtual machine files and configuration have their own defaults worth knowing during an investigation.

Item Location
VMMS Channel %SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Hyper-V-VMMS-Admin.evtx
Worker Channel %SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Hyper-V-Worker-Admin.evtx
VMSwitch Channel %SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Hyper-V-VmSwitch-Operational.evtx
Compute Channel %SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Hyper-V-Compute-Admin.evtx
Virtual Machine Configuration C:\ProgramData\Microsoft\Windows\Hyper-V\Virtual Machines\ (VMCX and VMRS files)
Virtual Hard Disks C:\Users\Public\Documents\Hyper-V\Virtual hard disks\ or a cluster shared volume
Cluster Shared Volumes C:\ClusterStorage\Volume1\ on clustered deployments
Windows Security Log %SystemRoot%\System32\Winevt\Logs\Security.evtx
SCVMM Logs C:\ProgramData\VMMLogs\ on the VMM management server
Pro Tip: A VHDX file copied off the host is a complete disk image of the guest. Monitor file share access (event 5145) and process creation for copy operations against the virtual hard disk directory, because that is exfiltration no guest agent will ever see.

Configuring Hyper-V Logging

Default channel sizes are small and several valuable channels are disabled. These commands establish adequate coverage on a Hyper-V host.

Step 1: Enlarge the Hyper-V Channels

$channels = @( "Microsoft-Windows-Hyper-V-VMMS-Admin", "Microsoft-Windows-Hyper-V-VMMS-Operational", "Microsoft-Windows-Hyper-V-Worker-Admin", "Microsoft-Windows-Hyper-V-VmSwitch-Operational", "Microsoft-Windows-Hyper-V-Compute-Admin", "Microsoft-Windows-Hyper-V-Config-Admin", "Microsoft-Windows-Hyper-V-High-Availability-Admin" ) foreach ($c in $channels) { wevtutil sl $c /ms:268435456 /rt:false } wevtutil gl Microsoft-Windows-Hyper-V-VMMS-Admin
Default channel sizes are around 1 MB, which wraps within hours on an active host. Retention set to false means overwrite as needed rather than stopping when full.

Step 2: Enable Windows Auditing on the Host

auditpol /set /subcategory:"Logon" /success:enable /failure:enable auditpol /set /subcategory:"Special Logon" /success:enable auditpol /set /subcategory:"Process Creation" /success:enable auditpol /set /subcategory:"File Share" /success:enable /failure:enable auditpol /set /subcategory:"Detailed File Share" /success:enable auditpol /set /subcategory:"Security Group Management" /success:enable # Include the command line in process creation events reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f
Detailed File Share auditing produces event 5145, which is what records a VHDX file being read across the network. Without the command line in 4688, process events lose most of their value.

Step 3: Enable PowerShell Script Block Logging

# Group Policy path: # Computer Configuration, Administrative Templates, Windows Components, # Windows PowerShell, Turn on PowerShell Script Block Logging reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /t REG_DWORD /d 1 /f reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging" /v EnableModuleLogging /t REG_DWORD /d 1 /f reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ModuleLogging\ModuleNames" /v Hyper-V /t REG_SZ /d Hyper-V /f
This is the only way to see PowerShell Direct sessions into guests. Event 4104 in the PowerShell Operational channel records the script block, including Enter-PSSession with a VMName parameter.

Step 4: Audit the Hyper-V Administrators Group

Get-LocalGroupMember -Group "Hyper-V Administrators" # Alert on membership change (event 4732 for local, 4728 for domain groups) Get-WinEvent -FilterHashtable @{LogName="Security"; ID=4732,4728,4756} -MaxEvents 100 | Where-Object { $_.Message -match "Hyper-V Administrators" } | Select-Object TimeCreated, @{N="Detail";E={$_.Message -split "`n" | Select-String "Account Name|Group Name"}}
Membership in this group grants full control of every guest without Domain Admin. Treat additions with the same urgency as a Domain Admin grant.

Step 5: Forward Channels to a Collector

# Windows Event Forwarding subscription (XPath filter on the collector) <QueryList> <Query Id="0"> <Select Path="Microsoft-Windows-Hyper-V-VMMS-Admin">*</Select> <Select Path="Microsoft-Windows-Hyper-V-Worker-Admin">*</Select> <Select Path="Microsoft-Windows-Hyper-V-VmSwitch-Operational">*</Select> <Select Path="Microsoft-Windows-PowerShell/Operational">*[System[(EventID=4104)]]</Select> <Select Path="Security">*[System[(EventID=4624 or EventID=4672 or EventID=4688 or EventID=5145)]]</Select> </Query> </QueryList>
Combining the Hyper-V channels with the relevant Security and PowerShell events in one subscription gives a complete picture of host activity in a single stream.

Step 6: Enable Shielded VM Attestation Logging

# On the Host Guardian Service Get-HgsTrace -RunDiagnostics -Detailed wevtutil sl "Microsoft-Windows-HostGuardianService-Attestation/Admin" /ms:104857600 # On the guarded host, confirm attestation status Get-HgsClientConfiguration | Select-Object IsHostGuarded, AttestationStatus, AttestationOperationMode
A host that fails attestation cannot start shielded machines. Attestation failures are worth alerting on because they can indicate boot configuration tampering on the host itself.
Security Note: Hyper-V analytic and debug channels contain far more detail but are disabled by default and can generate enormous volume. Enable them only for a specific investigation, and remember that enabling an analytic channel clears whatever it previously contained.

Hyper-V Threat Patterns

Hyper-V attacks exploit the host's privileged position over its guests. These are the techniques worth building detections around.

PowerShell Direct

Enter-PSSession with a VMName parameter opens a session inside a guest over the VMBus. Bypasses the guest firewall entirely, creates no network connection, and appears in no network log.
Detect Critical

Virtual Machine Export

Export-VM writes a complete copy of a machine including its disks to any path. Exporting a domain controller copies the entire directory database with every credential hash.
Detect Critical

VHDX Theft

Copying a virtual hard disk directly from the filesystem or a cluster shared volume. Mountable offline, defeating every access control inside the guest operating system.
Detect Critical

Virtual Switch Port Mirroring

Setting a virtual network adapter to mirror mode copies another guest's traffic to an attacker-controlled machine. Entirely invisible from inside the victim guest.
Detect High Risk

Checkpoint Manipulation

Creating a checkpoint captures memory contents including credentials, and reverting one can roll a machine back to before a patch was applied or an account was disabled.
Detect High Risk

Hyper-V Administrators Abuse

Membership grants complete control of every guest without Domain Admin, which makes it an attractive and frequently under-monitored escalation target.
Detect Critical
Security Note: A checkpoint of a running machine includes a memory image. Anyone who can read the resulting AVHDX and VMRS files can extract credentials, encryption keys, and in-memory secrets without ever authenticating to the guest.

Critical Hyper-V Event IDs

These identifiers span the Hyper-V channels and the Windows Security log. Both are needed for a complete picture.

Event ID Channel and Meaning Why It Matters
13002 VMMS: Virtual machine created New machines outside the provisioning process are attacker infrastructure, often used as a foothold inside the trusted network
13003 VMMS: Virtual machine deleted Destructive, and also used to remove a temporary clone after its disks have been copied
13004 / 13005 VMMS: Virtual machine imported or exported Export writes a full copy of a machine including disks. The clearest bulk exfiltration event Hyper-V produces
18500 / 18502 Worker: Virtual machine started or stopped Individually routine, but many stops within minutes precedes disk-level encryption or theft
18304 / 18306 VMMS: Live migration started and completed Unexpected migration can indicate a machine being relocated to a host the attacker controls
20415 VMMS: Checkpoint created A checkpoint of a running machine captures memory, exposing credentials and keys to anyone who can read the files
4104 PowerShell: Script block executed The only host-side record of PowerShell Direct. Search the script block text for VMName parameters
4688 Security: Process created With command line auditing enabled, captures Export-VM, Copy-Item against VHDX paths, and vmconnect usage
5145 Security: Network share object access checked Records VHDX files read over the network, which is disk-level exfiltration no guest agent will observe
4732 / 4728 Security: Member added to a group Additions to Hyper-V Administrators grant total control over every guest without Domain Admin
26010 VMSwitch: Port setting changed Mirroring configuration on a virtual port copies another guest's traffic to an attacker-controlled machine
Pro Tip: Correlate host event 4104 containing a VMName parameter against guest event 4624 with logon type 3 and no corresponding network connection. That combination is the signature of PowerShell Direct, and it is essentially invisible from the guest alone.

Hyper-V Log Analysis Queries

These PowerShell and SIEM queries cover guest access, machine theft, and network interception on a Hyper-V host.

PowerShell Direct Sessions
PS> Get-WinEvent -FilterHashtable @{LogName="Microsoft-Windows-PowerShell/Operational"; ID=4104} | Where-Object { $_.Message -match "-VMName|-VMId|VMConnect" } | Select-Object TimeCreated, UserId, @{N="Script";E={$_.Message.Substring(0,200)}}
The only reliable detection for PowerShell Direct. Without script block logging enabled, these sessions leave no host-side trace at all.
Virtual Machine Export
PS> Get-WinEvent -FilterHashtable @{LogName="Microsoft-Windows-Hyper-V-VMMS-Admin"; ID=13005,13004} | Select-Object TimeCreated, Id, Message
Export copies an entire machine including its disks. Reconcile every occurrence against a documented backup or migration task.
VHDX File Access
SIEM> source="WinEventLog:Security" EventCode=5145 RelativeTargetName="*.vhdx" OR RelativeTargetName="*.avhdx" | stats count, values(RelativeTargetName) by SubjectUserName, IpAddress | sort - count
A VHDX read across the network is a full disk image leaving the host. Only backup service accounts should ever appear here.
Mass Guest Shutdown
SIEM> source="WinEventLog:Microsoft-Windows-Hyper-V-Worker-Admin" EventCode=18502 | bucket _time span=10m | stats dc(VmName) as vms by _time, Computer | where vms > 10
Bulk shutdown precedes disk-level encryption, since VHDX files cannot be encrypted while the machine holds them open.
Hyper-V Administrators Changes
SIEM> source="WinEventLog:Security" EventCode IN (4728,4732,4756) TargetUserName="Hyper-V Administrators" | table _time, SubjectUserName, MemberName, Computer
Equivalent in impact to a Domain Admin grant in a virtualised estate, and far less frequently monitored.
Port Mirroring Enabled
PS> Get-VM | Get-VMNetworkAdapter | Where-Object { $_.PortMirroringMode -ne "None" } | Select-Object VMName, Name, PortMirroringMode, SwitchName
A guest adapter in Destination mode receives copies of other machines' traffic. Outside a documented troubleshooting exercise this is interception.
Checkpoint Activity
PS> Get-VM | Get-VMSnapshot | Select-Object VMName, Name, SnapshotType, CreationTime | Where-Object { $_.CreationTime -gt (Get-Date).AddDays(-7) }
Recent checkpoints on production machines, especially domain controllers, capture memory contents including credentials.
Unexpected Virtual Machines
PS> Get-VM | Select-Object Name, State, CreationTime, @{N="Notes";E={$_.Notes}} | Where-Object { $_.CreationTime -gt (Get-Date).AddDays(-30) } | Sort-Object CreationTime -Descending
Machines created outside the provisioning pipeline. An attacker-created guest sits inside the trusted network with no endpoint agent on it.
Console Connections
SIEM> source="WinEventLog:Security" EventCode=4688 (New_Process_Name="*vmconnect.exe" OR CommandLine="*vmconnect*") | table _time, SubjectUserName, CommandLine, Computer
vmconnect opens the virtual console, giving keyboard access to a guest with nothing inside the guest recording how the session arrived.
Channel Health Check
PS> Get-WinEvent -ListLog "Microsoft-Windows-Hyper-V-*" | Select-Object LogName, IsEnabled, MaximumSizeInBytes, RecordCount | Where-Object { $_.MaximumSizeInBytes -lt 100MB }
Channels still at their small defaults wrap within hours. Run this as a scheduled configuration check across the cluster.

Best Practices for Hyper-V Logging

Apply these practices so the hypervisor layer is as well monitored as the guests running on it:

01

Enable PowerShell Script Block Logging

PowerShell Direct travels over the VMBus and produces no network evidence. Event 4104 on the host is the only record that a session was opened into a guest.

02

Enlarge the Hyper-V Channels

Defaults around 1 MB wrap within hours on a busy host. Raising them to 256 MB costs almost nothing and preserves days rather than hours of history.

03

Treat the Host as a Windows Server

Events 4624, 4672, 4688, and 5145 apply here exactly as anywhere else, and are frequently more informative than the Hyper-V specific channels.

04

Audit Hyper-V Administrators Like Domain Admins

Membership grants complete control of every guest without any domain privilege. In a virtualised estate the two groups are functionally equivalent.

05

Monitor VHDX File Access

Enable Detailed File Share auditing so event 5145 records disk images being read. A copied VHDX is a full disk exfiltration that no guest agent will ever see.

06

Alert on Export and Checkpoint Operations

Both produce a complete copy of a machine, and checkpoints of running guests additionally capture memory containing credentials and keys.

07

Never Run Domain Controllers on a Domain-Joined Host

If the host is a member of the domain it hosts, compromising the domain compromises the hypervisor and vice versa. Break that circular dependency.

08

Forward Everything to a Collector

Windows Event Forwarding with a subscription covering the Hyper-V channels plus the relevant Security and PowerShell events puts the full picture in one place off the host.

Common Hyper-V Log Examples

An attack against a Hyper-V host, from privileged group abuse to guest disk theft.

Escalation via Hyper-V Administrators

Log Name: Security Event ID: 4732 Task Category: Security Group Management Description: A member was added to a security-enabled local group. Subject: Account Name: CORP\helpdesk-svc Logon ID: 0x4E2A1C Member: Account Name: CORP\r.almutairi Group: Group Name: Hyper-V Administrators Group Domain: HV-PROD-04
A helpdesk service account adding a user to Hyper-V Administrators. That single membership grants full control over every guest on the host, including domain controllers, with no Domain Admin required.

Host Logon and Privilege Assignment

Log Name: Security Event ID: 4624 Logon Type: 10 (RemoteInteractive) Account Name: r.almutairi Account Domain: CORP Source Network Address: 10.99.4.117 Logon Process: User32 Event ID: 4672 Privileges: SeSecurityPrivilege, SeBackupPrivilege, SeRestorePrivilege, SeTakeOwnershipPrivilege, SeDebugPrivilege
An RDP logon from a VPN pool address followed by special privilege assignment. SeBackupPrivilege alone allows reading any file on the host, including every VHDX.

PowerShell Direct into a Domain Controller

Log Name: Microsoft-Windows-PowerShell/Operational Event ID: 4104 Level: Warning Description: Creating Scriptblock text (1 of 1): $c = Get-Credential; Enter-PSSession -VMName "DC01-PROD" -Credential $c ScriptBlock ID: 8f2a1c04-1122-4e91-b7d2-0010f4e21b00 Path:
A session opened directly into the domain controller over the VMBus. The guest will log a 4624 with no matching network connection, and the guest firewall never saw a thing.

Domain Controller Exported

Log Name: Security Event ID: 4688 New Process Name: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe Process Command Line: powershell.exe -c "Export-VM -Name DC01-PROD -Path E:\temp\.stage" Creator Subject: CORP\r.almutairi Log Name: Microsoft-Windows-Hyper-V-VMMS-Admin Event ID: 13005 Description: Virtual machine 'DC01-PROD' was exported successfully. (Virtual machine ID a1b2c3d4-1122-6874-0000-0010f4e21b00)
The command line from event 4688 and the VMMS confirmation together prove what was exported, by whom, and to where. Without command line auditing, event 13005 alone would not name the destination.

VHDX Copied Off the Host

Log Name: Security Event ID: 5145 Description: A network share object was checked to see whether client can be granted desired access. Subject: Account Name: r.almutairi Logon ID: 0x4E2A1C Network Information: Source Address: 10.99.4.117 Share Name: \\*\E$ Relative Target Name: temp\.stage\DC01-PROD\Virtual Hard Disks\DC01-PROD.vhdx Access Request Information: Accesses: ReadData (or ListDirectory)
The exported disk being read across the administrative share. That file contains NTDS.dit and every credential hash in the domain, extractable offline with no authentication to the guest.

Traffic Interception via Port Mirroring

Log Name: Microsoft-Windows-Hyper-V-VmSwitch-Operational Event ID: 26010 Description: Port setting changed on switch 'Prod-vSwitch'. Port: 8f2a1c04-... VM: TEST-UTIL-09 Adapter: Network Adapter Setting: PortMirroringMode Old Value: None New Value: Destination
An unremarkable test machine set as a mirroring destination now receives copies of every other guest's traffic on that switch. Nothing inside the victim guests indicates this is happening.

Checkpoint Capturing Live Memory

Log Name: Microsoft-Windows-Hyper-V-VMMS-Admin Event ID: 20415 Description: Checkpoint operation for 'DC01-PROD' completed successfully. Checkpoint type: Standard (includes memory state) Files: C:\ClusterStorage\Volume1\DC01-PROD\Snapshots\ a1b2c3d4-1122-6874-0000-0010f4e21b00.VMRS (memory) DC01-PROD_8f2a1c04.avhdx (disk delta)
A standard checkpoint of a running domain controller writes a full memory image to the VMRS file. Anyone who can read that file can extract credentials and keys directly from memory.

Mass Shutdown Preceding Encryption

Log Name: Microsoft-Windows-Hyper-V-Worker-Admin Event ID: 18502 'SQL-PROD-01' was turned off (09:58:02) Event ID: 18502 'APP-PROD-03' was turned off (09:58:03) Event ID: 18502 'FILE-PROD-02' was turned off (09:58:03) Event ID: 18502 'WEB-PROD-01' was turned off (09:58:04) Event ID: 18502 'DC01-PROD' was turned off (09:58:05)
Five machines stopped in four seconds. VHDX files cannot be encrypted while a running machine holds them open, which makes bulk shutdown the last practical warning before the damage becomes irreversible.
